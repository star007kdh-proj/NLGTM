# <project> 규약과 분해 축

요구사항이 아니라 "이 설계에서 상태가 어떻게 갈라지는가"를 적는다. 짧을수록 좋다. 하드웨어든 소프트웨어든 형식은 같다.

## 1. 분해 축

| 축 | 클래스 | 적용 블록 |
|---|---|---|
| <예: bank / slot / tenant / 요청 종류> | <클래스 나열> | <블록> |
| 부하 | idle / 매 cycle(매 요청) busy | sweep, reset, GC, retry, replacement 로직 전부 |
| 큐·버퍼 포인터 | 빈 / 가득 / wrap | 모든 큐 |
| 실패 모드 | 정상 / 부분 실패 / 재시도 / 타임아웃 | 외부 의존이 있는 경로 전부 |
| 설정 게이트 | <파라미터, feature flag 이름> | 전체 |

## 2. 형제 경로

같은 상태를 소비하는 경로 목록. 한 경로의 가드가 다른 경로에 없으면 버그 후보.

- <상태>: <소비자 A>, <소비자 B>, ...

## 3. 인코딩 규약

- <인덱스/태그/포인터/ID 인코딩. 비교 시 양쪽이 같은 규약이어야 하는 것들>
- <초기화 없는 상태의 취급>

## 4. 관측

- 카운터·메트릭 정의 방식과 이름 규칙
- 신호·로그 지정 시 정의 파일:라인 동반

## 5. 빌드

- 컴파일/타입체크 명령, 최소 설정
